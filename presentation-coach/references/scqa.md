# SCQA 框架参考

**来源**: Barbara Minto · McKinsey，广泛应用于BCG、Bain、Deloitte
**适用**: 战略提案、问题诊断、咨询演讲、任何需要建立紧迫感的商业场合

---

## 核心哲学

人类的大脑天生被"问题-解答"结构吸引。
SCQA 的核心技巧是：**在给出答案之前，先让听众自己产生那个问题。**
当他们心里已经有了疑问，你的答案就会像钥匙插入锁孔一样自然。

---

## 四个组件

### S — Situation（情境）
听众已经知道并认可的背景事实。
- **目的**: 建立共识基础，让所有人站在同一起点
- **原则**: 只说听众会点头认同的内容 — 不要在这里引入新信息
- **长度**: 1-3句话，不超过30秒
- **示例**: "过去两年，我们的线下门店销售额保持稳定，数字渠道占比从12%增长至31%。"

### C — Complication（冲突）
打破稳定情境的变化、威胁或矛盾。
- **目的**: 制造紧迫感，让听众感受到"现在必须做决定"
- **原则**: 冲突必须真实且与听众切身相关 — 不能夸大
- **类型**:
  - 外部威胁: 竞争对手动作、市场变化、监管政策
  - 内部矛盾: 资源限制、增长瓶颈、战略不一致
  - 机会窗口: 时间有限的机会，不行动就会错过
- **示例**: "但最新用户研究显示，72%的高价值客户表示，如果我们的App体验不在6个月内改善，他们会转向竞争对手。"

### Q — Question（核心问题）
由情境+冲突自然引发的那个问题。
- **目的**: 明确你要回答什么 — 也是听众心里已经浮现的问题
- **原则**: 这个问题必须由S和C逻辑推导而来，不能跳跃
- **格式**: 通常是一个决策问题或方向问题
- **示例**: "那么我们应该如何在资源有限的情况下，优先改善哪些体验节点？"

### A — Answer（答案）
你的核心结论或建议 — 这就是金字塔原理的顶端。
- **目的**: 直接回答Q，不拐弯抹角
- **原则**: 先给答案，再给支撑（后续幻灯片展开）
- **示例**: "我们建议集中资源重构结账流程和个性化推荐两个节点，预计可将高价值用户留存率提升25%。"

## 三种叙事模式

根据你与听众的关系和场合，选择不同的展开顺序：

| 模式 | 顺序 | 适用场景 |
|---|---|---|
| **标准模式** | S → C → Q → A | 听众对背景不熟悉，需要建立共识 |
| **直接模式** | A → S → C → Q（倒叙） | 高管时间极度有限，直接从结论开始 |
| **悬念模式** | S → C → Q → [展开分析] → A | 需要让听众跟着你思考，结尾给答案 |

**建议**: 董事会用直接模式；战略提案用标准模式；需要说服怀疑者时用悬念模式。

## 执行步骤

### 第一步 — 写出SCQA四段
分别用1-3句话写出S、C、Q、A，总计不超过2分钟口头表达。

### 第二步 — 检验逻辑链
- S → C: "正因为[情境]，所以[冲突]才令人担忧" ✓
- C → Q: "面对[冲突]，自然会问[问题]" ✓  
- Q → A: "[答案]直接回答了[问题]" ✓

如果任何一步感觉跳跃，补充过渡信息。

### 第三步 — 展开支撑结构
A之后，用金字塔结构展开3个支撑论点（参考 `pyramid.md`）。

### 第四步 — 设计冲突可视化
C（冲突）通常是整场演讲最有力的幻灯片：
- 用一个数字表达冲突的规模（"72%的用户表示..."）
- 用时间轴表达紧迫感（"6个月窗口期"）
- 用对比表达差距（"我们 vs 竞争对手"）

---

## 输出格式

交付以下内容：
1. **SCQA四段文本** — 完整口头表达版本（含建议语气和节奏）
2. **叙事模式建议** — 说明为何选择该模式
3. **冲突幻灯片设计** — 如何将C可视化
4. **答案展开结构** — A之后的3个支撑论点框架
5. **逻辑链检验** — 确认S→C→Q→A逻辑无跳跃
6. **一句话版本** — 将整个SCQA压缩为一句话电梯陈述
