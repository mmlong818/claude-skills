# AutoResearchClaw 流水线阶段详解

## 概述

AutoResearchClaw 实现了一个 23 阶段、8 阶段的全自动研究流水线。本文档详述每个阶段的输入、输出、关键逻辑与注意事项。

---

## Phase A：研究范围界定

### 阶段 1 — TOPIC_INIT
- **输入**: 用户提供的原始研究主题字符串
- **输出**: 结构化研究意图（主域、子域、关键词、研究问题类型）
- **逻辑**: LLM 解析主题，识别研究领域归属，提取核心研究问题
- **注意**: 主题越具体，后续阶段质量越高；避免过于宽泛的主题

### 阶段 2 — PROBLEM_DECOMPOSE
- **输入**: 阶段 1 的结构化研究意图
- **输出**: 层级化问题树（主问题 → 子问题 → 具体研究点）
- **逻辑**: 将研究问题递归分解，识别问题间的依赖关系
- **注意**: 问题树深度建议不超过 3 层，避免过度细化

---

## Phase B：文献发现

### 阶段 3 — SEARCH_STRATEGY
- **输入**: 问题树
- **输出**: 多源检索策略（含关键词组合、检索 API 优先级、过滤条件）
- **检索源**: arXiv、Semantic Scholar、CrossRef
- **逻辑**: 为每个子问题生成 3-5 个关键词组合，覆盖同义词和相关术语

### 阶段 4 — LITERATURE_COLLECT
- **输入**: 检索策略
- **输出**: 原始文献列表（标题、摘要、作者、年份、引用数、DOI/arXiv ID）
- **目标数量**: 通常收集 50-200 篇候选文献
- **注意**: 使用真实 API 调用，避免伪造文献元数据

### 阶段 5 — LITERATURE_SCREEN ⚙️ *[人工审批门 1/3]*
- **输入**: 原始文献列表
- **输出**: 筛选后的核心文献列表（通常 20-50 篇）
- **筛选标准**: 相关性评分、发表年份（优先近 5 年）、引用数、期刊/会议质量
- **人工审批**: 用户可在此阶段调整筛选标准或手动添加/移除文献

### 阶段 6 — KNOWLEDGE_EXTRACT
- **输入**: 核心文献列表
- **输出**: 结构化知识库（方法、数据集、结果、局限性、研究空白）
- **逻辑**: 逐篇提取关键信息，按主题聚类存储

---

## Phase C：知识综合

### 阶段 7 — SYNTHESIS
- **输入**: 结构化知识库
- **输出**: 综合报告（共识、分歧、研究空白、趋势）
- **方法**: 多智能体辩论——多个 LLM 角色（支持者、反对者、中立者）对知识点进行辩论
- **注意**: 辩论结果通过多数表决或置信度加权综合

### 阶段 8 — HYPOTHESIS_GEN
- **输入**: 综合报告
- **输出**: 2-5 个可验证研究假设（含置信度评分、验证方法建议）
- **格式**: `假设 H{n}: [陈述]，置信度: {score}，验证方式: [方法]`

---

## Phase D：实验设计

### 阶段 9 — EXPERIMENT_DESIGN ⚙️ *[人工审批门 2/3]*
- **输入**: 研究假设
- **输出**: 详细实验方案（基线模型、评估指标、消融实验设计、数据集）
- **人工审批**: 用户确认实验设计的可行性与资源需求

### 阶段 10 — CODE_GENERATION
- **输入**: 实验方案
- **输出**: 可执行 Python 代码（含数据加载、模型训练、评估、可视化）
- **硬件检测逻辑**:
  ```python
  if torch.cuda.is_available():
      device = "cuda"      # NVIDIA GPU
  elif torch.backends.mps.is_available():
      device = "mps"       # Apple Silicon
  else:
      device = "cpu"       # 回退 CPU
  ```
- **沙箱要求**: 代码须在隔离环境中执行

### 阶段 11 — RESOURCE_PLANNING
- **输入**: 实验代码、硬件检测结果
- **输出**: 资源需求评估（内存、GPU 显存、预估运行时间、存储需求）

---

## Phase E：实验执行

### 阶段 12 — EXPERIMENT_RUN
- **输入**: 实验代码、资源计划
- **输出**: 原始实验结果（日志、指标、模型检查点）
- **监控**: NaN/Inf 实时检测，内存溢出捕获
- **超时**: 默认 2 小时，可配置

### 阶段 13 — ITERATIVE_REFINE
- **触发条件**: 实验失败（异常、超时、指标异常）
- **自愈逻辑**:
  1. 捕获错误信息
  2. LLM 分析错误根因
  3. 生成修复补丁
  4. 重新执行（最多重试 3 次）
- **输出**: 修复后的代码 + 成功执行的结果

---

## Phase F：分析与决策

### 阶段 14 — RESULT_ANALYSIS
- **输入**: 实验结果
- **输出**: 统计分析报告（均值、标准差、置信区间、显著性检验、可视化图表）
- **图表类型**: 折线图、箱型图、热力图、消融对比柱状图

### 阶段 15 — RESEARCH_DECISION
- **输入**: 分析报告 + 原始假设
- **决策逻辑**:
  | 条件 | 决策 |
  |------|------|
  | 结果达到预期指标 | `PROCEED` → 进入 Phase G |
  | 结果接近但未达标 | `REFINE` → 调整超参数，返回阶段 12 |
  | 结果与假设严重不符 | `PIVOT` → 重新生成假设，返回阶段 8 |
- **最大循环次数**: REFINE 最多 3 次，PIVOT 最多 2 次

---

## Phase G：论文写作

### 阶段 16 — PAPER_OUTLINE
- **输入**: 假设、实验结果、分析报告
- **输出**: 详细论文大纲（含各章节要点、图表分配、字数规划）
- **标准结构**: Abstract → Introduction → Related Work → Methodology → Experiments → Conclusion

### 阶段 17 — PAPER_DRAFT
- **输入**: 大纲 + 所有前序产出物
- **输出**: 完整论文草稿（5,000–6,500 词）
- **逐章节生成**: 每章独立调用 LLM，确保连贯性
- **图表集成**: 将统计图表嵌入对应章节

### 阶段 18 — PEER_REVIEW
- **输入**: 论文草稿
- **输出**: 多智能体评审报告（含具体修改建议）
- **评审维度**:
  - 方法论严谨性
  - 实验设计合理性
  - 结果解读准确性
  - 写作清晰度
  - 贡献声明强度
- **评审角色**: Area Chair、Reviewer 1、Reviewer 2、Reviewer 3（不同专业背景）

### 阶段 19 — PAPER_REVISION
- **输入**: 草稿 + 评审报告
- **输出**: 修订后论文 + 修改日志（Response to Reviewers 格式）
- **逻辑**: 逐条处理评审意见，记录接受/拒绝及理由

---

## Phase H：最终化

### 阶段 20 — QUALITY_GATE ⚙️ *[人工审批门 3/3]*
- **输入**: 修订后论文
- **检查项**:
  - [ ] 字数在目标范围内
  - [ ] 所有图表有标题和标注
  - [ ] 引用格式一致
  - [ ] 无明显语法错误
  - [ ] 所有声明有实验支撑
- **`--auto-approve` 模式**: 自动通过所有检查（适用于 CI/CD 或批量研究场景）

### 阶段 21 — KNOWLEDGE_ARCHIVE
- **输入**: 本次研究全程数据
- **输出**: 存档至知识库的 6 类条目：
  1. **decisions**: 关键决策及理由
  2. **experiments**: 实验配置与结果
  3. **findings**: 核心发现
  4. **literature**: 重要文献摘要
  5. **questions**: 未解决的研究问题
  6. **reviews**: 评审意见摘要
- **时间衰减**: 30 天半衰期，旧经验权重逐渐降低

### 阶段 22 — EXPORT_PUBLISH
- **输入**: 最终论文、BibTeX、图表
- **输出**:
  - `paper.tex` (NeurIPS/ICML/ICLR 模板)
  - `references.bib`
  - `figures/` 目录
  - `paper.pdf` (通过 pdflatex 编译)

### 阶段 23 — CITATION_VERIFY
- **输入**: BibTeX 引用列表
- **四层验证**:
  1. **真实性检查**: 通过 API 确认引用存在于真实数据库
  2. **相关性评分**: 引用与被引用内容的语义相关性
  3. **一致性检查**: 论文中的引用陈述与原文一致
  4. **反伪造守卫**: 检测 LLM 幻觉生成的虚假引用
- **通过标准**: 所有引用真实性 100%，相关性评分 ≥ 0.7

---

## 人工审批门总结

| 门控阶段 | 位置 | 默认行为 | `--auto-approve` |
|---------|------|---------|-----------------|
| 阶段 5 — LITERATURE_SCREEN | Phase B 结束 | 等待人工确认文献列表 | 自动使用系统筛选结果 |
| 阶段 9 — EXPERIMENT_DESIGN | Phase D 开始 | 等待人工确认实验方案 | 自动使用生成的实验方案 |
| 阶段 20 — QUALITY_GATE | Phase H 开始 | 等待人工最终审阅 | 自动通过质量检查 |

---

## 错误处理与回滚

| 错误类型 | 处理策略 | 回滚目标 |
|---------|---------|---------|
| 文献 API 失败 | 切换备用 API，重试 3 次 | 阶段 4 |
| 代码执行错误 | 自愈修复（最多 3 次） | 阶段 12 |
| 实验结果异常 | REFINE/PIVOT 决策 | 阶段 8 或 12 |
| LaTeX 编译失败 | 修复 LaTeX 语法错误 | 阶段 22 |
| 引用验证失败 | 移除无效引用，补充真实引用 | 阶段 23 |
